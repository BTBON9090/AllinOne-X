# 4.4.6 图层工作流

## 超级选择

| 范围 | 查询对象 |
|---|---|
| 全页 | 当前页面全部后代，包含实例内部和隐藏图层 |
| 子孙 | 选中对象自身及全部后代 |
| 内在 | 选中容器全部后代，排除所有选中根对象 |
| 子级 | 选中对象的直接子级 |
| 同级 | 每个选中对象所在父级的子节点，排除全部选中对象 |

非全页范围需要选中起点。查找并选中结果后切换范围/筛选，继续使用原起点；用户在画布主动更改选择后才更新起点。重叠范围按节点 ID 去重。

每组多选为 OR；类型、状态、名称及高级属性组之间为 AND。排除表示“该组一个也不能命中”；空组不限制。隐藏与锁定包含父层继承，Auto Layout 支持组件与实例，Slot 按原生类型或 slotContentId 引用识别，不按名称猜测。

## 组件构建

普通构建有单个组件、多个组件、组件集三种。截图中的错误来自转换后读取失效 Frame 的 parent。当前实现先保存父级，在副本上转换和合并，所有分组成功才删除原 Frame；失败清理副本。选区包含相互嵌套的 Frame 时先报错，避免重复转换同一子树。

AI 构建步骤：

1. 读取选中的根对象概要（ID、名称、尺寸、颜色、形状等），按原比例导出截图。分析阶段不遍历子图层、不向模型发送子树。
2. 支持 Frame、独立组件、一个或多个已有组件集。默认整合模式将已选组件集内所有实际变体作为目标，与 Frame 一起重新规划属性；800 上限按实际来源对象计数。关闭整合模式则保留原有补入语义：既有属性固定，参考图最多 20 张另成一批。
3. AI 仅给出分组、组件名称和实际存在的变体属性和值。截图不能可靠确定内部绑定路径，所以不推测 TEXT、BOOLEAN、INSTANCE_SWAP、SLOT 的绑定。普通构建的可选属性能力仍可用。
4. 三阶段分析：每批最多 20 个对象，观察完整差异并暂存（包括批内恒定属性与简短证据）；全局规划按功能用途划分组件族、分配所有批次分组、确定至多 12 个统一属性；最后按规划映射属性和值、补充有依据的常量。插件按组件族及可兼容的父级/目标集强制归并，AI 的局部分组名称不再决定最终集合边界。每个对象恰好出现一次，所有成员具有相同属性键。缺少属性时要求 AI 修正，不能把未知填成“无”。
   草稿允许不同来源 ID 暂时有相同属性组合。先通过全局规划找遗漏的内容、配色、边框、编辑入口等真实维度；最终仍无法区分时，才保留全部冲突成员为独立组件。始终不编造编号属性、不补造缺失组合、不改写原始外观。
5. 整合模式创建一个或多个新的组件族副本，原组件集、原对象和实例关联保持原状。合并来源必须处于同一父级。原集合在分析后新增/删除变体或改变名称/属性会要求重新分析；失败清理所有副本。关闭整合模式后，再次选中已有组件集和剩余 Frame/组件可继续分析和补入。Figma 原地添加，不替换组件集或已有组件 ID；独立主组件并入新集合时保留其 ID 和实例关联。最终仍有重复组合或不兼容属性的对象全部保留为独立组件，明确列出原因；宿主写入前的严格校验仍保留，不能将冲突计划直接写入组件集。
6. MasterGo 公开 ComponentSet API 不提供 appendChild/insertChild。运行时不具备该能力时，原组件集保留，拟补入对象先作为独立组件并明确提示；新建组件集使用原生 combineAsVariants。不会通过重建原组件集来假装补入成功。
7. 点击构建后才修改画布。在本地校验原始图层与生成内容的填充、描边、效果、尺寸、内部位置、字体和文本；这些本地校验数据不发送给 AI。差异或后续分组失败时回滚草稿并保留原对象。
8. 根对象快照和目标集合的实际属性在应用前复核；已有名称和样式变化会要求重读。分析后发生的内部内容变化仍以构建时原内容为准，不由 AI 重绘。

构建内的语言组件集已移除。组件清洗的“AI 名称翻译”将选中组件/组件集名称译为英文，保留变体结构与真实属性 ID。

## 查重和命名

- 分段匹配：按连字符、下划线、空格、点和斜杠切词，比较完整词段。`cart` 不会作为词段匹配 `cartography`。
- 子串匹配：比较连续字符片段，上述名称可能命中，适合更宽松的粗筛。
- AI 语义精筛：依据名称过滤语义不同的误匹配，不读取图片；改为 Switch。
- AI 视觉查重：独立于名称候选对，移除通用词后导出两个所选容器的直接子对象（不递归展开内部子树），以精确节点 ID 比较截图。只给出相同/相似建议和原因，不删除图层；结果行可定位两侧，名称可单独定位一侧。需选择互不嵌套的容器。结果每页最多渲染 200 对，更多匹配分页查看，避免大量同图匹配撑满 DOM；当前会话内跨页勾选保留。
- 图层命名：根据截图建议含义/功能名称，不加入颜色或线性、填充等外观词。逐批显示只读草稿，点击标题定位。全部批次完成后，AI 统筹所有命名结果并统一术语；只输出必要的全局名称映射与单项修正，未修正项视为确认。统筹完成后才可编辑、勾选并应用，显示完成通知；继续解析跳过已识别对象。入口是静态导航，不依赖 AI 模块动态创建。默认一个通用名；多含义模式最多六个相关词组，使用 `、` 分隔，避免 `/` 创建资产层级。
- 不使用 AI 时，可用普通编号命名、原有名称查重与手工组件构建。

“清理名称中的 ID 后缀”只移除显示名称末尾的 `#123:456`。真实属性 ID 仍由宿主管理，用于属性/实例引用，不会删除。

## 性能和失败处理

| 操作 | 单次上限 / 分批 |
|---|---|
| AI 组件方案 | 合计 800 个对象（含已有组件集变体）；每批最多 20 个待处理对象，后批复用前批属性命名规则，最后统筹所有批次 |
| 图层命名 / 名称翻译 | 800 个对象；识图命名每批最多 20 个，翻译每批 15 个 |
| 视觉查重 | 两侧直接子对象合计 800 个；60 个以内全量交叉比较；更大选区全量匹配相同 JPEG 预览，其余由双向最近 4 个视觉候选交给 AI，可能漏掉弱相似项，UI 明示 |
| 子图层树 | AI 分析不读取。构建时仅在本地执行外观保护，每个根对象最多 5,000 层，超过时明确报错并保留源对象 |
| 图片 | 最长边 384 px，不放大小图、不改变长宽比；UI JPEG 0.78；每批原始图片最多 6 MB；统一请求入口强制每次最多 20 张（含参考图、格式修复） |
| CompKit AI | 800 个实际变体，每批最多 20 张图；全部属性值、实际组合和尺寸统计随图提供，重复组合去重 |

网络使用会话级串行队列，请求起始间隔至少 1 秒。429 立即暂停该端点，按照 Retry-After 设置冷却期（缺省 30 秒），已排队请求也不会继续发往受限服务。不自动重试 HTTP 错误；单次请求超时 120 秒。结构错误最多修复一次。正常情况下会自动处理所有批次，再执行最终统筹，没有每轮八次请求的人工暂停。

命名、组件方案、视觉查重、CompKit 在每批成功后保存草稿；429、网络错误、格式失败、取消均保留先前批次。点击继续解析从未完成批次开始，已识别名称不会重新请求。组件全局属性规划和最终统筹接收全部批次的文字分析结果，不重复发送图片；属性规划单独保存，统筹中断时只重试统筹。组件方案 UI 区分三阶段：观察差异、全局属性规划、按属性整合；其余工作流区分分批分析和统筹分析，完成前不开放 AI 结果应用。CompKit 可主动修改轴选择以退出未完成 AI 流程、回到手动排列。

视觉查重每轮最多上传两侧合计 20 张截图；成功比较的批次（包括无匹配批次）全部保存并提交最终统筹。相同预览的笛卡尔匹配用两侧 ID 列表压缩成一个候选组，避免将 160000 对重复证据展开给 AI；最终确认后才显示可操作的分页结果。大选区的候选筛选仍可能漏掉弱相似项，统筹不补造不存在的匹配。

输出截断单独处理：`length` / `max_tokens` 携带的内容如果完整且通过业务校验则保留；真正截断的批次自动减半，成功子批次立即更新断点。新批次沿用已缩小的上限，最大仍为 20 张。单个对象仍截断时暂停，不进入无穷重试。参考图也保存自己的已完成子批次；视觉查重拆分必须保留左右两侧全部笛卡尔组合。最终统筹不能丢掉部分输入，只允许使用精简输出提示重试一次，失败后保留全部批次等待手动继续。

仅对官方支持关闭思考的已识别型号（GLM 4.7、5/5.1/5.2、DeepSeek V3.2/V4/Flash/Pro）发送 `thinking.type=disabled`，不为未知型号添加不兼容参数。依据：[Z.AI 思考模式](https://docs.z.ai/guides/capabilities/thinking-mode)、[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。这减少默认思考对输出预算的占用，不代表能解除服务商额度或速率限制。

启动/导航不再自动请求 AI 问候，只显示本地或当日缓存；用户点击问候后才请求。网络队列同时识别标准 HTTP 429 和代理以 HTTP 200 返回的 429 错误体。

分析阶段不再自动发送数字图片进行能力测试，设置页仍可手动测试。内置文本代理及已知文本模型会提示更换；其他模型直接使用实际工作图片，错误时显示原因并暂停。长任务有保持插件打开提示；取消尽可能终止请求。退出或重启插件不会自动恢复进度，快照和续传状态只存在当前插件会话中（最多八次读取快照）。

应用阶段不提供中途取消；成功修改可使用宿主撤销。所有图片和名称只通过用户已配置的 AI 服务发送，普通功能不依赖 AI。

## CompKit

矩阵排列与说明书共用一页，底部“生成说明书”开关默认关闭。每个属性分配为列、行或分组，单轴支持多个属性。AI 分批查看变体根截图，并参考全部实际属性值、维度基数、稀疏组合和尺寸统计，给出最多三种有区别的建议（均衡、状态对比、紧凑浏览）及逐维原因；可切换建议再手动调整。每批建议先暂存；全部截图完成后，再由 AI 结合全部批次建议、实际属性组合和尺寸统筹，最后提供可选布局。未统筹完成的批次建议不会改写轴选择或执行排列。不会补齐不存在的变体或重绘组件。

共享布局算法覆盖普通矩阵、单个说明书和批量目录。每列/行按该列/行最大尺寸计算，剩余属性分组，重复组合用额外位置显示，不覆盖。无 Y 轴时仍正确累加分组高度。

- 横纵间距：单元格边缘之间的间距；较小节点对齐单元格左上角。
- 组件集内边距：组件集边界到矩阵单元格的距离。
- 说明书外边距：说明书边界到内容区域的距离。
- 区域间距：说明书内容块之间的间隔。
- 分组间距：矩阵不同属性分组之间的间隔。

去掉矩阵舞台额外硬编码的 24 px 内边距和隐式居中偏移。关闭圆角时会重置旧圆角。输入按控件边界规范化并回写显示值，零值有效。编辑目录中的一个组件集会保留同目录其他组件集。

## 内置组件族 skill

源文件：[component-family-synthesis/SKILL.md](../shared/skills/component-family-synthesis/SKILL.md)。构建脚本读入此文件，将其嵌入 Figma 和 MasterGo 的 UI；它是插件运行资源，不是另行安装到项目的个人 Codex skill。三个组件 AI 阶段均使用同一规则。

头像示例按尺寸、形状、内容、配色、边框、编辑入口等已观察属性归为 Avatar；摄影头像的相机遮罩属于编辑状态，不自动改成“相机内容”。真正不同用途的按钮保持独立。已有小集名称仅作为证据，不是分组约束。

整合通过复制源组件并创建新集合实现；不会迁移旧实例到新副本。原有内部组件属性的跨集合绑定不由 AI 推测重建，原集合保持可用。宿主原生复制行为依据：[Figma ComponentNode](https://developers.figma.com/docs/plugins/api/ComponentNode/)、[MasterGo ComponentNode](https://developers.mastergo.com/apis/componentNode.html)。

## 验证与限制

自动化覆盖（网络及画布 API 使用测试替身，不等于真实云模型性能实测）：

- `npm run verify`：双平台编译、UI 语法、等价、填充/名称/本地化/窗口以及图层、AI 契约测试。
- `npm run check:layer-workflows`：800 对象读取/命名/构建、801 拒绝、根对象子级读取被禁止时仍可分析、部分命名连续应用；新增组件与旧主组件 ID 保留、原地补入、重复组合拒绝、后续分组失败回滚、MasterGo 缺少组件集插入 API 的保守降级；颜色与尺寸保护；重复组合隔离后，经宿主构建的独立组件与合法组件集均保持源颜色、尺寸、圆角和内部文字。
- `npm run check:ai-contracts`：每次 20 图硬限制、800 对象紧凑统筹、严格对象覆盖、跨批映射与拆分、无虚构变体、全局语义命名、JSON 包裹、串行队列、429 冷却与队列停发、Retry-After、排队取消。
- `npm run check:layer-ui`：双平台 Chrome 440/340 px；800 名称的 40 个成功批次、中途 429、一次格式修复、统筹阶段 429 与单独续传；参考图单独批次、组件方案草稿/统筹合并，视觉查重与 CompKit 分批暂存/最终统筹，真实截图请求、无子树载荷、点击标题定位、命名导航和紧凑按钮。
- `npm run check:component-families`：150 个头像/10 个外观分组归并为一个组件族，真实属性组合唯一；不同用途保留为不同族，缺失属性与来源被拒绝。
- `npm run check:component-families-ui`：双平台多组件集 150 个目标、8 个图片批次；全局属性规划/最终整合分别遭遇限流并独立恢复，完成图片不重传，同族多个返回小组被归并。宿主套件同时检查 150 变体整合副本、失败回滚、原组件 ID/颜色/尺寸/内部文字保留和原集变化检测。
- `npm run check:component-conflicts-ui`：双平台 150 对象在 80、100 项遇到限流后续传；第 5 批重复组合仍计入进度，最终跨批冲突自动隔离为独立组件；所有来源恰好保留一次，前 80 项不重传，不反复请求统筹，单批图片不超过 20 张。
- `npm run check:ai-recovery-ui`：双平台 150 对象 20→10→5 缩批、成功子批保存后 429 续传、完整但标记截断的 JSON、统筹精简重试、矩阵缩批、查重交叉组合不遗漏、单对象失败有界；workspace 回归验证启动零问候请求。
- 既有 workspace、window-bookmarks、localization 浏览器套件覆盖所有导航、三种窗口尺寸、键盘与拖拽、中英文和主题。

未使用用户模型凭据或真实 Figma/MasterGo 文档执行端到端修改。插件重启原因及真实模型效果仍需实机验收。截图足以支持保守的视觉分组、语义命名、相似比较和排列建议；不能保证推断不可见状态、隐藏子层或内部属性绑定，因此这些内容不会根据截图自动改写。

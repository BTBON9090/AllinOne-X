## 目标与边界

面向在画布旁高频操作的设计师。保留紫色品牌、常规/精简窗口、14 个功能入口、22 项简易工具，以及两个宿主的现有能力。遵循 btdesign 的任务结构、语义视觉变量、渐进披露和实际渲染复查流程；没有进行用户访谈，不声称已证明任务效率提升。

改动只在新分支；不合并原开发分支，不改独立 MasterGo 仓库的主分支。本仓库内 Figma 与 MasterGo 同步为 4.3.0。

## 布局选择

根据本轮截图反馈，收回首版的分组导航、重复页头与搜索/分类。效率工具的入口数量有限，优先全部直接展示，不要求用户先分类再查找。

| 方式 | 组织与密度 | 适用与代价 |
| --- | --- | --- |
| 有标签的侧栏（默认） | 112px 侧栏；14 个入口直接排列；工具最多三列 | 当前功能由侧栏选中态说明，不重复设置页面标题 |
| 图标轨道（精简） | 44px 侧栏；同一套功能；标签通过提示保留 | 给内容更多空间，适合熟练用户；需学习图标，不能作为唯一模式 |

两者共用内容和任务路径，而非维护两份缩水功能。默认窗口 440×600，精简 360×520，回归额外覆盖 340×440。

### 层级规则

1. 宿主标题栏已经承载插件名称；插件内不再重复品牌栏和全局标题。
2. 首页保留用户要求的 AI 每日问候，下面直接显示 22 项工具，每项图标 + 名称，三列、最小高度 54px；普通与精简中文窗口首屏均可见。英文长名称允许换行，小窗口可滚动，不截断操作名。
3. 工作区与页面使用同一个表面。超级选择、尺寸助手、组件构建、设置等分组不再画外框，也不再贡献第二层 padding。以 12/18 的小节标题和 16px 组间距表达归属，主要内容左右仅一层 10px 边距。
4. 功能内容负责滚动，执行区保持可达。尺寸编辑在预设库前，底栏显示实际 W×H。
5. 保留设置页和子设置页必要的返回操作、键盘焦点和工具说明；不把去掉装饰框误解为删除状态或操作信息。

## 视觉契约

| 角色 | 浅色 | 深色 / 说明 |
| --- | --- | --- |
| 页面底色 | `#ffffff` | `#222128` |
| 面板表面 | `#ffffff` | `#222128` |
| 正文 | `#262331` | `#f3f0fa` |
| 辅助文字 | `#625e70` | `#c1bccf` |
| 当前项 / 链接 | `#7135db` | `#b997ff` |
| 选中背景 | `#eee7fb` | `#36294c` |
| 主操作按钮 | `#7135db` + 白字 | 两种主题保持相同按钮配对 |
| 输入 / 筛选背景 | `#f1f1f5` | `#2c2a34`；默认透明描边，聚焦仍显示紫色轮廓 |

使用系统无衬线栈，含 PingFang SC / Microsoft YaHei 回退。子页标题 13/20、600；小节 12/18、600；正文 12/18、400；按钮与选项 11/16、400–600；辅助 10/14、400。主操作 12/16、600，普通按钮及文本输入约 30px 高；切换项 26–28px。这是桌面密度选择，不宣称适合所有触摸环境。所有操作控件统一 4px 圆角（包括旧版内联大圆角），输入和按钮显式设定行高。原生单选圆点、色块等有意义形状不被强制方形化。图标保持离线 Tabler 线性家族、16px 槽位、1.75 笔画。

只保留 120–140ms 的颜色/侧栏宽度反馈；遵循减少动态设置，不用动效表示任务完成。选中状态以底色和文字强调，焦点使用独立轮廓；默认轮廓只用于必要的固定操作区分界，不再为每张卡、每个标签添加描边。未进行完整 WCAG 合规认证。

## 功能与算法调整

- 共享路由注册管理显示面板、可访问名称、导航状态和设置返回；面板滚动位置按会话保留。
- 修复组件清洗的标签切换误清除 CompKit 标签状态；尺寸分类浏览不再修改目标尺寸，手动编辑会取消旧预设高亮，超界尺寸明确提示而非静默截断。
- 移除全局查找和工具过滤代码及两个模板，避免保留不可达的旧交互；工具说明仍保留在原有工具提示和可访问描述中。
- 语言操作说明改为依据当前 action 和界面语言生成纯文本，修复固定翻译键覆盖动态说明以及 HTML 标签外露，不修改宿主翻译算法。
- 智能填充按内容关系区分结构：基础类型保留两列，每项以单层浅底色关联标题、设置与副选项，不加描边、阴影或外层卡片。短选项优先与标题同行，长选项只在自身分组内换行；组间距 6px、组内间距 2–4px、最小高 36px。分组根据内容增高，窄窗口滚动而不压缩或重叠；普通中文窗口首屏仍展示 19 种类型。移除基础填充内的“发送到 AI”，AI 生成仍是独立标签页。
- 自定义字段保留每条一行：标题 + 顺序 / 随机 / 编辑 / 删除。去掉数量统计和重复填充入口，标题仅作名称，不会误触填充。长标题单行省略并保留完整提示，英文窄窗口也不挤掉右侧操作。
- 自定义数据编辑页在保存按钮右侧提供两个纯图标操作：Tabler 列表图标用于顺序录入，交叉箭头用于随机录入，附中英文悬停提示与可访问名称。使用点击时的当前草稿，保留输入顺序、忽略空行，支持共享前后缀；录入不保存草稿或退出编辑。录入中禁用两按钮，结果和空内容/无选区提示在编辑页可见，窄窗口底栏保持可达。编辑标题也在切换语言时保持编辑状态。
- 三种来源共用底部前后缀栏。勾选前缀/后缀后，所选来源的填充内容追加到原文字前/后；输入框内字符通过“+”或 Enter 单独添加到原文字，允许标点和有意输入的空格。未选择位置或输入为空时提示，不替换原文。
- 基础、自定义、AI 与直接添加字符统一先捕获选区，再提交填充；模式和自定义/AI 数据在点击时快照，等待期间改选项或编辑列表不改变该次任务。填充处理中禁用执行按钮，结果由宿主消息确认。
- 问候语恢复为 18px / 24px、700 字重，使用主文字色，并保留 1–2 个亲切的 emoji；长文案均衡换行。问候语按本地日期和界面语言缓存；配置 AI 后可自动生成，点击刷新可换一句。请求去重、15 秒超时并清理监听器；AI 不可用时显示与当前时间匹配的简短本地问候，不影响功能入口。问候语中的 emoji 不转换成操作图标，旧缓存若没有 emoji 会补一个。浏览器测试模拟 AI 响应，没有向真实服务发送测试请求。
- 数列参数保留 0；按序生成不再被遗留随机/升降序排序覆盖。阶乘增量计算，质数只试除 6k±1 候选；超界明确报错，不静默归零或截断。
- 单次数列/文本批量上限 10,000；精确阶乘范围 0–18；质数上限 10,000,000；其他数值不超过 JavaScript 安全整数量级。需要更大精度时应采用 BigInt 或十进制定点方案，而非伪装精确。
- 时间严格校验时分秒，允许零与负步长；先对步长取模，跨午夜和大步长不溢出。
- 文本遍历使用显式栈，避开深层递归溢出；排序改为先按 Y 排序、再按固定行锚点分组，消除不满足传递性的比较器。
- 填充继续使用请求时的顺序；节点删除或读取失败不使整个批次卡住，也不让后续节点拿到前一项数据。
- 自定义列表标题用文本节点渲染，保留用户原文而不当成 HTML。

## 验证与限制

可复现检查入口：

- `npm run verify`：双端构建、内嵌 UI 语法、组件构建静态检查、双平台入口等价、字体与填充行为、数列算法。
- `npm run check:workspace-ui`：真实 Chromium 中运行两端 UI，模拟宿主消息；14 路由 × 3 尺寸，深浅/中英、三列与首屏可见性、控件实际圆角/行高、卡片零 padding/零描边、键盘、滚动恢复、设置返回、尺寸底栏、数列预览、四种来源的前后缀消息、标点与空格保留、自定义列表单行对齐和安全标题、每日问候缓存与失败回退、动态语言说明。

字体测试覆盖混合字体、缺失字体和局部失败；排序测试覆盖选区顺序变化、节点位置变化、隐藏祖先与 12,000 层嵌套。数列测试覆盖全部 10 种数字数列、零/负参数、精度上限和跨午夜时间。

截图用于复查分组、对齐、文字换行和控件层级；浏览器检查不等于真实宿主画布验收。尚未进行真实文件下的 Figma / MasterGo 操作、屏幕阅读器全流程、跨系统字体与用户任务测试。发布前应在副本文件验证智能填充、文字替换、组件构建、语言 Mode 和 PPT 导出，不以模拟结果代替上线确认。

## 后续改进方案（未在本轮扩张实现）

1. **P1：高风险批量操作统一预览与撤销。** 给删除隐藏图层、清洗、语言替换增加影响数量和差异预览，统一撤销入口。先用副本场景验证“取消不写入、局部失败可恢复”，避免每个操作都弹重复确认。
2. **P1：继续拆分单体面板。** 将文字查找、语言 Mode、组件清洗各自拆成模板、状态机和宿主适配器；统一请求 ID、超时、取消和过期响应丢弃。先迁移语言流程并补乱序/重试测试，不一次重写全部功能。
3. **P2：持久化常用参数。** 优先提供可命名的填充/尺寸预设，放在对应功能内，不重新引入首页分类、搜索、收藏分区。只存本地配置，保留可导入导出能力。用常见连续任务比较步骤数和误触，而不只统计点击量。
4. **P2：数据与文案治理。** 尺寸库区分官方物理参数和推导设计视口，逐条记录来源、日期与缩放依据；统一遗留中英文文案、单位、错误码和术语。此次未重新核验设备规格。
5. **P2：大文件性能预算。** 对 1k / 5k / 10k 图层建立遍历、字体加载、UI 列表渲染基准；按实测再引入分批处理、取消和虚拟列表，避免未测量就增加复杂度。

## 项目级复验记录

用户指出首版重复页头、搜索分类、多层卡片与大圆角降低了空间利用率。本轮按 btdesign 的“先判断关系是否需要容器”原则，保留功能分组语义但取消其视觉卡片外壳，并将密度落实到实际控件与首屏测试，而非仅缩小字体。单选标签的透明输入仍需以自身标签为定位容器，去卡片时不能丢失这项关系；已保留定位并通过真实点击验证。这些结论限定于此效率插件，不推导为所有界面都不能使用卡片或搜索。

后续填充反馈说明：名称和设置属于同行，不能为了显式操作拆成两行；固定内置类型适合网格，自定义名称长短不一则适合单行列表。实现中发现旧 `.smart-label` 的 8px 下边距使标题看似同行却未垂直居中，已局部清零并加入真实边界框对齐断言。图标继续复用 better-icons 工作流已收录的离线 Tabler 素材，不混入新的图标风格。

2026-10-08：用户指出纯留白网格使副选项与标题显得分散。按 btdesign 的归属关系原则，将选项移入标题的同一排布流，并使用无描边浅底共同区域；不是恢复多层嵌套卡片。窄窗口测试发现自动网格行会压缩换行内容，改为按内容高度排布，并检查每个按钮均在所属分组内。补充可访问分组名称，保留副选项只改规则、名称才执行填充的区别。

本轮浏览器检查发现共享路由误用了旧版独立底栏 ID，导致超级选择切换中断；改为兼容现有嵌套底栏并增加每次导航单面板/单选中态断言。单选标签原来将原生 input 设为 display:none，键盘无法选择；改为可聚焦的透明输入层并保留可见焦点。此经验限定在本项目的遗留结构，不据此建立所有 UI 必须有底栏或隐藏输入的规则。

2026-10-13：新增窗口贴边气泡和锚点拖拽排序。按 btdesign 的状态保留与直接可达原则，收起不销毁 DOM、分组不折叠；普通中文窗口保留全部 14 个入口首屏可见。精简模式合并收起/拖拽入口，避免增加底栏高度。实际拖拽检查发现 Chromium 在重排节点时可能释放鼠标捕获并丢失焦点，改为全局拖拽结束/取消监听，并在 DOM 移动后恢复捕获，保留键盘排序与 Esc 取消。平台能力、验证范围见 [WINDOW_AND_BOOKMARKS.md](WINDOW_AND_BOOKMARKS.md)。

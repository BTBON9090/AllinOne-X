# All in One for MasterGo

这是 AllinoneX 4.0.0 的 MasterGo 实现，与同仓库 `../figma/` 版本同步维护。

## 文件说明

- `manifest.json`：MasterGo 插件清单。
- `main.ts`：使用 `mg` API 的主线程源码。
- `main.js`：可直接加载的编译产物。
- `ui.html`：完整插件界面、AI 请求、PPT 生成及交互逻辑。
- `assets/all-in-one-logo.png`：原 Figma 插件使用的紫色格子 Logo，供发布 MasterGo 插件时上传。
- `scripts/`：UI 语法和功能等价检查。

## 实例逆向与组件构建器

插件将一键逆向放在首页“简易工具”，而“实验室 → 组件构建”只负责 Frame 组件化：

1. **实例逆向母版**
   - 在“简易工具”中只选择一个 Instance 后点击“实例逆向”。
   - 从实例当前状态创建新的本地组件母版，原实例保持不变；新母版从原实例右侧 48px 开始放置，连续逆向时会继续向右避让已有结果，不覆盖原实例或前一次结果。
   - 逆向时递归恢复各层子层顺序，并恢复全部后代的 `FILL / STRETCH`、绝对定位、尺寸边界、显隐和锁定状态；`min/maxWidth/Height` 只会在 MasterGo 允许的 Auto Layout 容器或子层上恢复，避免宿主约束写入报错。属性引用只有在路径、图层名和类型都匹配时才会回绑。
   - 如果源实例来自组件集，会优先读取原组件集全部真实子组件；团队库代理不开放 `children` 时，按组件目录 `parentId` 精确补齐，仍不可读时再通过单属性切换搜索真实 `mainComponent`。不会根据属性做笛卡尔积，也不会猜测颜色、圆角或间距。
   - 完整组件集一次最多还原 100 个真实变体。确认原组件集超过 100 个时不再报错或批量生成，但仍保持组件集类型：组件集中只生成当前实例对应的一个真实变体，并保留原组件集的全部属性维度、当前值和非变体属性。没有实体组件的属性组合允许为空，不会为其制造占位变体。
   - 每个真实变体都会从原组件创建临时实例并独立还原，合并后按变体数量和实际组件节点身份校验完整性；任何一个变体缺失都会回滚。MasterGo 对子组件名称的自动规范化只会提示，不会再造成“数量相同却逆向失败”。选中的变体保留当前实例覆盖，其余变体保留原母版默认外观；若某个未选中变体因已删除节点引用而不能实例化，会直接从原组件结构恢复，结构也不可读时再使用视觉快照兜底。
   - 尽量保留文字、布尔、实例切换、变体属性、属性别名、首选实例范围和子层属性引用。未被实例覆盖的文字/布尔属性会继续恢复原有变量绑定；存在覆盖时优先保留当前值并提示。
   - 组件集的非变体属性只有在真实图层成功绑定后才会创建；缺少引用时，会用临时实例的文字哨兵值或布尔显隐差异定位对应图层。没有对应图层或绑定失败的非变体属性会被跳过/删除；源组件集已有的变体属性即使当前只有单一取值或存在空组合也会保留。
   - 实例切换属性若引用了已删除节点，会尝试改用逆向结果中当前子实例的有效母版；仍无法解析时只跳过该属性，不中断整个逆向。
   - 逆向会安全读取并重映射原型交互目标，失效交互只会被跳过；若原生解绑因孤立组件节点失败，会自动降级为逐层安全复制，并把无法继续绑定的孤立实例还原成 Frame。
   - 若当前选中实例连结构和视觉快照都不可读，会继续从其原组件直接恢复；原组件内完全不可读的叶子实例会降级为保留尺寸、名称和根层样式的 Frame 占位，不再因为一个已删除节点引用终止整个组件集。此时未映射到组件属性的手工覆盖无法保证保留，并会在结果警告中明确说明。
   - 若宿主连逐层结构复制都无法读取，最后会导出实例当前 PNG 外观并放入本地组件容器，保证动作仍有结果；该结果会明确标记为“视觉快照兜底”，不会伪称内部图层和属性已恢复。
   - 组件生成事务与自动选中、视口定位、撤销记录分别容错；后处理失败只会作为警告，不再把已成功生成的母版误报成“逆向失败”。
2. **Frame 铸造组件**
   - 支持选择一个或多个 Frame。
   - 可选择“单个组件”“多个组件”或“组件集”。多选合成单个组件、以及创建组件集时，Frame 需要位于同一父级。
   - 可选把全部文字（包括纯数字文本）和嵌套实例暴露为组件属性；两项默认均不勾选。
   - 创建组件集时可自定义变体属性名，默认使用 `Variant`，每个 Frame 名称作为变体值。
   - 组件集会先完成变体合并，再在组件集上统一创建文字/实例属性；相同语义路径跨变体共用一个属性，并自动保证属性名唯一。
   - 为避免原型连接目标丢失，连接了 Connector 的 Frame 会被安全拦截，不执行转换。

两项能力使用 MasterGo 原生 `createComponent`、`combineAsVariants` 和组件属性 API。Frame 构建会转换所选 Frame；实例逆向只处理自动创建的副本或安全复制结果，不替换、移动或解绑原实例。

## 构建

```bash
npm install
npm run verify
```

构建产物为 `main.js`。在 MasterGo 客户端中打开“插件 → 开发者模式 → 创建/添加插件”，选择本目录的 `manifest.json` 即可加载。

## 插件图标

![All in One Logo](assets/all-in-one-logo.png)

MasterGo 的开发版 `manifest.json` 不提供插件图标字段，因此从本地清单安装时不会读取自定义 Logo。发布插件时，请在发布信息页面的“插件 LOGO”位置上传 `assets/all-in-one-logo.png`；这是原 Figma 版使用的紫色格子图标。

## 平台差异

- 主线程使用 MasterGo 的 `mg` API 和 `mg.document.currentPage`。
- 插件 UI 保留原有布局、交互和中英文文案。
- 网络请求在 UI iframe 中执行；MasterGo 主线程沙箱不支持 `fetch`/XHR。
- 图片、样式、变量、自动布局、页面切换和图层类型均使用 MasterGo 对应 API。
- 多语言使用 MasterGo Collection / Mode / Variable；优先采用原生文本内容绑定，并为 API 版本差异提供兼容同步层。
- 矢量图层在界面中仍显示为“矢量”，内部自动映射为 MasterGo 的 `PEN` 节点。

## 功能等价检查

`npm run verify` 会执行 TypeScript 构建、UI 脚本语法检查，并对比 Figma 与 MasterGo 版本的功能入口、消息处理分支和关键 UI 元素，避免迁移时遗漏功能。

当前双平台基线：68 个主线程消息分支、13 个导航功能入口、296 个 UI 元素 ID、306 个国际化键。

超级选择器现可正确读取“内在 / 子级 / 子孙”范围；智能填充的自定义字段同时提供顺序与随机两种分配方式。

`npm run verify` 还会执行组件构建器专项静态检查，确认三种构建模式、两类属性生成、实例副本保护和默认未勾选状态。若同仓库 `../figma/` 不存在 Figma 版 `code.ts` / `ui.html`，跨平台等价检查会自动跳过，其余检查仍正常执行。

## AI 结合方向

面向组件构建器的 AI 产品研究、分阶段路线和安全执行架构见 [`docs/component-builder-ai-roadmap.md`](docs/component-builder-ai-roadmap.md)。推荐优先实现“AI 属性架构师”：AI 只输出可审阅的组件构建计划，由确定性 MasterGo API 执行，避免模型直接进行不可控的画布变更。
